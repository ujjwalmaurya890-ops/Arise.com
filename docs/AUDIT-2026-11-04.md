# ARISE — Engineering Audit, 2026-11-04

Scope: full repository `ujjwalmaurya890-ops/Arise.com` at `0cf3de7` (main), audited
and worked on branch `arena/cf2163be-arise-com`.

Every finding below was reproduced before it was written down. Anything that
looked suspicious on inspection but turned out to be correct is listed in
§7 "Rejected findings" so the next person does not re-investigate it.

| | |
|---|---|
| Frontend | Vanilla ES5/ES2020 widgets, no framework runtime; ~102 top-level widget modules under `src/`, 127 JS files total, 3.2 MB |
| Shell | `index.html` (single page) + `assets/app-bundle.js` (React shell) + `src/cloud/auth-entry.js` |

| Styling | 8 top-level stylesheets + per-feature CSS; design tokens in `styles/design-system.css`, motion tokens in `styles/animation-upgrade.css` |

| Dependencies | 3 runtime (`fflate`, `firebase`, `firebase-admin`), 7 dev |
| Git | 11 commits on `main` before this branch; no CI configuration in the repo |

Engineering quality is **above average for a project of this shape**: the
storage bridge is deliberately designed and documented, the service worker has
a network deadline and refuses to cache HTML under asset URLs, the build refuses
to publish `server/`, `netlify/`, `config/`, `tests/` or `.env`, and
`mount-safety.js` isolates widget failures. The defects below are concentrated
in the seams *between* these systems, and in observability: several mechanisms
correctly detect a problem and then drop the result.

## 2. Findings

Severity: **Critical** = data loss / account compromise; **High** = a core
feature silently broken or a security control absent; **Medium** = degraded UX
or maintainability with a user-visible effect; **Low** = polish; **Optional** =
worth doing, not a defect.

### F1 — One corrupt journal entry permanently wedges cloud sync
- **File:** `src/cloud/storage-bridge.js:20-23` (`recover()`), `:284-287` (`cleanJournal()`)
- **Problem:** both call `JSON.parse()` on a stored journal value with no guard.
  `recover()` is called from `CloudSync.initialize()` (`sync-engine.js:73`), so a
  single truncated/tampered/older-format value throws out of initialization and
  the account never syncs again. `cleanJournal()` runs on every flush retry of
  the same marker, so the queue cannot drain either.
- **Why it matters:** the journal is the *only* local record of a mutation that
  has not reached the server. The failure mode is silent: the user sees an
  unsynced account and no explanation.
- **Solution:** validate instead of trusting `JSON.parse` success; quarantine
  unreadable entries; keep recovering valid ones in order.
- **Difficulty:** S · **Benefit:** high · **Risk:** low (defensive only)
- **Test:** `tests/cloud/journal-resilience.test.cjs`
- **Severity: Critical** · **Status: fixed in `d4836b7`**

### F2 — Widget dialogs have no focus trap, no focus-in, no focus restore
- **File:** `src/animation-upgrade.js:277` (`bindModalA11y`)
- **Problem:** the helper documents Escape, initial focus, Tab wrapping and focus
  restoration, and is exported — but **no file in `src/` calls it**. Every widget
  dialog (expenses PDF, local-files preview, certificates, command palette) let
  Tab walk into the page behind it, never received focus on open, and dropped
  focus to `<body>` on close.
- **Why it matters:** WCAG 2.2 AA 2.1.2 (No Keyboard Trap is satisfied; the
  opposite — *no* containment — is 2.4.3 Focus Order and 3.2.1), and for
  keyboard/switch users a dialog that never receives focus is unusable.
- **Solution:** fix the helper (visibility without layout, Escape ownership for
  stacked dialogs, focus restore) and adopt every dialog from its existing
  markup via a mutation-bus scan, so ~100 widget files need no edits.
- **Difficulty:** M · **Benefit:** high · **Risk:** low (purely additive)
- **Test:** `tests/test-modal-focus-trap.cjs` (16 assertions)
- **Severity: High** · **Status: fixed in `e84f0f9`**

### F3 — 72 rendered controls have no accessible name
- **Evidence:** `.probe/a11y-audit.cjs` mounts every `src/*.js` widget in jsdom
  with a valid store and counts interactive controls without a name → **72**
  (duplicate ids: 0, images without alt: 0).
- **Problem:** two patterns dominate. Text/number inputs whose only hint is a
  `placeholder` (which disappears on input and is not reliably announced as the
  name), and `type=file` inputs driven by a visible button, which announce
  nothing when focused.
- **Solution:** one observer patch following the existing `src/a11y-*-patch.js`
  pattern: unambiguous visible label → placeholder → de-kebab-cased semantic
  attribute; hidden file inputs take the name of the button that opens them
  (scored by import/restore verbs) or the accepted file type. Never overwrite an
  existing name and never invent one.
- **Difficulty:** M · **Benefit:** high · **Risk:** low
- **Test:** `tests/test-a11y-accessible-names.cjs` (21 assertions)
- **Severity: High** · **Status: fixed in `9753bfe`**

### F4 — Day keys are unpadded, so string ordering is wrong for 9 months of the year
- **File:** `src/widget-shared-utils.js` (`dayKey`, `startOfDay`, `daysBetween`)
- **Problem:** `dayKey()` produced `YYYY-M-D`. `"2026-1-9" > "2026-1-10"` is true
  lexically, so every lexical sort/bucket comparison broke for January–September,
  and two widgets rendered raw keys as labels.
- **Solution:** zero-padded keys (same storage identity), `weekLabel()` for
  display, `dayKeyToDate()` at LOCAL midnight, DST-safe `daysBetween`.
- **Test:** `tests/test-day-key-utils.cjs` (18 assertions)
- **Severity: High** (silent wrong data in streaks/momentum) · **Status: fixed in `9da8ee0`**

### F5 — Widgets blank out on wrong-shaped stored data
- **Files:** `src/career-command-center-widget.js` (`r.filter is not a function`),
  `src/learning-heatmap-widget.js` (`Invalid time value`)
- **Problem:** `JSON.parse` succeeding was treated as the value having the shape
  the caller needs. A JSON `null`, an object where an array was expected, or a
  string where a timestamp was expected threw during render and the panel went
  blank.
- **Principle recorded:** *`JSON.parse` succeeding ≠ the value having the shape
  the caller needs.*
- **Test:** `tests/test-corrupt-storage-resilience.cjs` (12 assertions)
- **Severity: High** · **Status: fixed in `4afa124`**

### F6 — The mirror proxies are an open, unbounded scraping relay
- **Files:** `netlify/functions/{leetcode,codechef,gfg}.js`
- **Problem:** all three sent `Access-Control-Allow-Origin: *` on every
  response, cached results in a plain `Map` with no eviction for the life of the
  warm lambda, and had no per-client budget. Any page on the internet could call
  them from a visitor's browser and spend the deployment's egress IP and
  upstream quota harvesting those sites.
- **Solution:** shared `_proxy-guard.js` — origin allow-list (configured origin
  or the request's own Host), per-client budget with `429` + `Retry-After`,
  LRU-bounded cache.
- **Test:** `tests/test-proxy-hardening.cjs` (10 assertions)
- **Severity: High** · **Status: fixed in `91f7b63`**

### F7 — The CSP constrains nothing
- **File:** `netlify.toml:130`
- **Problem:** the entire policy was `base-uri 'self'` — no fetch directives at
  all. Any injected `<script src="//attacker/x.js">` loaded and ran with the
  user's session and study data.
- **Solution:** full policy (see the file for the directive-by-directive
  justification). **Honest limitation:** `script-src` still needs
  `'unsafe-inline'` because `index.html` ships six inline bootstrap blocks;
  removing it requires per-response nonces, which a static header cannot
  generate. What *is* enforced: no remote script origin, no `'unsafe-eval'`, no
  wildcards anywhere, no plugins, no framing, explicit `connect-src`.
- **Test:** `tests/test-csp-policy.cjs` (12 assertions)
- **Severity: High** · **Status: fixed in `418b002`** · **Follow-up:** nonce migration (§4)

### F8 — The widget loader's failure hook was never defined
- **Files:** `index.html:1076` calls `window.__ariseReportWidgetError`, documented
  as "if defined elsewhere". No file in the repository defined it.
  `window.__ariseWidgetLoadFailures` is written and never read.
- **Consequence:** a chunk that 404s or times out = an empty tab with no
  explanation, and no hint that reloading would help.
- **Solution:** `src/widget-failure-reporter.js` defines the hook, adopts
  failures recorded before/after boot, and shows one polite dismissible status
  line (not a modal, not a toast per failure).
- **Test:** `tests/test-widget-failure-reporter.cjs` (16 assertions)
- **Severity: Medium** · **Status: fixed in `f362192`**

### F9 — The mutation bus swallows every subscriber error
- **File:** `src/mutation-bus.js` dispatch loop (`catch {}`)
- **Problem:** 42 widget updaters subscribe. A throwing updater froze on stale
  data with no console entry, no `__ariseMountErrors` entry, nothing.
- **Solution:** record each distinct failing subscriber (name, count, timestamps,
  message), forward to the reporter, keep neighbour isolation.
- **Test:** `tests/test-mutation-bus-failures.cjs` (12 assertions)
- **Severity: Medium** · **Status: fixed in `abde839`**

### F10 — Whole-document rescans on every mutation burst
- **Files:** `widget-shared-utils.js` + 5 dashboard widgets
- **Problem:** each subscribed widget ran its own `document.querySelectorAll`
  pass per burst; measured **51 `querySelectorAll` calls and 25,092 elements
  returned** for a fixed workload.
- **Solution:** one coalesced pass per burst (80 ms trailing, skipped when
  hidden).
- **Measured:** 26 calls / 12,792 elements — **~49% fewer rescans and elements**.
  Elapsed time unchanged (jsdom cost is dominated by widget rendering, not
  queries) — no wall-clock claim is made.
- **Test:** `tests/test-updater-coalescing.cjs` (9 assertions)
- **Severity: Medium** · **Status: fixed in `7b15109`**

### F11 — ~~No CI configuration in the repository~~ WITHDRAWN — this finding was wrong
- **Claimed:** no `.github/workflows`, so `npm test` only ran when a human
  remembered.
- **Reality:** `.github/workflows/secure-sync.yml` exists and is tracked. It runs
  on every pull request and on pushes to `main` and `arena/**`: `npm ci`,
  `npm run build`, `npm test`, `npm audit --audit-level=high`, the Firestore
  emulator rules tests, and the Chromium browser checks.
- **How I got it wrong:** I checked for the directory only as part of an early
  structure listing, did not re-check it while writing findings, and then
  published a "no CI" claim that the first merged PR's own check run disproved.
  It was caught after the merge, by looking at the PR's status checks.
- **Lesson recorded:** a negative claim ("X does not exist") needs the same
  evidence standard as a positive one — a single `ls` at the start of a session
  is not that evidence, because the tree can be inventoried before it is
  understood.
- **Severity: n/a** · **Status: withdrawn** · **Verdict: the project's CI is
  better than this audit claimed.**

### F12 — `npm run test:rules` cannot pass without a local Firestore emulator
- **File:** `package.json` → `tests/emulator/firestore-rules.test.cjs`
- **Problem:** the script is part of the documented test surface but requires
  the emulator. A skip is not a pass, and reporting it as green would be wrong.
- **Severity: Low** · **Status: documented, not fixed** (needs an environment
  decision — emulator in CI vs. documenting it as manual).

### F13 — Service-worker network deadline is a fixed 3 s
- **File:** `service-worker.js:5` (`NETWORK_DEADLINE_MS = 3000`)
- **Problem:** on a slow-but-working connection the cached shell always wins
  after 3 s, so the page can render stale with no indication.
- **Assessment:** the worker's overall design is careful (atomic install,
  refuses HTML under asset URLs, `no-store` for the secure bundle). Changing the
  deadline is a tuning decision that needs real network traces, not a guess.
- **Severity: Low** · **Status: proposed, needs measurement**

### F14 — `mount-safety.js` records mount errors nobody surfaces
- **File:** `src/mount-safety.js:14`
- **Problem:** `window.__ariseMountErrors` was written for a human to read in
  devtools — unavailable on a phone.
- **Status: fixed as part of `f362192`** (the reporter reads it).

### F15 — `journalHealth()` / bus `failures()` are diagnostics with no UI
- **Status:** both now feed the reporter banner. **Severity: Low**

### F16 — Duplicate `nav-active` styling across three stylesheets
- **Files:** `styles/design-system.css`, `styles/animation-upgrade.css`, plus a
  feature sheet.
- **Assessment:** visual only, no functional defect observed; consolidating risks
  changing the established look. **Severity: Low** · **Status: not changed on
  purpose** (see §7).

## 4. Roadmap (what I would do next, in order)

CI already exists (see the withdrawn F11), so the roadmap starts with real work:

1. **CSP nonce migration** (#1) — the remaining half of F7. Needs the six inline
   bootstrap blocks moved to same-origin files (#8) first.
2. **`npm test` should not depend on a prior build** — the CSP test added in
   this branch read `dist/`, which the CI workflow happens to create before
   running tests, masking the problem for anyone running `npm test` alone on a
   fresh clone. Fixed in PR #26; the general rule is that tests may only read
   committed files.
3. **A11y role/state sweep** (#10) — names are done; states are not.
4. **Adaptive SW deadline** (F13) — after collecting real timings.
5. **Dead-code duplication** (#12) — cheap, safe, reduces review surface.
6. **`test:rules` locally** (F12) — CI runs it in the emulator; document how to
   run it locally so a skip is never mistaken for a pass.

## 6. Security review

Checked and found **clean**:

- No credentials, private keys or service-account JSON in the client bundle;
  `scripts/build.mjs` actively rejects them.
- `.env` is git-ignored and excluded from the build; `config/` is not published.
- No `eval`, `new Function`, or dynamic code construction anywhere in `src/`.
- No `document.write`; widget HTML is built from escaped user data in the files
  inspected (the reporter added here treats filenames as text).
- Account isolation is real: the storage facade prefixes every key with the
  encoded UID and throws without an active session.
- `git log` contains no secrets; history is shallow (11 commits).

Fixed during this work: F6 (open CORS + unbounded cache + no rate limit),
F7 (CSP), F1 (data-integrity hardening).

Open: rate limiting on `/api/sync` and `/api/cloud` beyond what the session
check already provides; CSP nonce migration.

## 7. Rejected findings (do not re-investigate)

Recorded so this work is not repeated. Each was checked and found **not** to be
a defect.

| Looked wrong | Why it is fine |
|---|---|
| Motion tokens defined twice with different values (`design-system.css:141-144` vs `animation-upgrade.css:33-49`) | The later sheet *deliberately* re-declares `--motion-standard` / `--motion-slow` as aliases to the newer scale, with a comment saying so. It is one resolved vocabulary, not two systems. |
| `storage-watch-bus.js` drops the first value written to a key that did not exist | **I got this wrong once and reverted it.** The expression `t !== lastValue && (lastValue = t, t !== null)` already fires when `lastValue` is `null` and `t` is a real value: the assignment happens before the null comparison. My "fix" changed nothing; the only failing assertion was my own source-level guard. Reverted without a commit. |
| CSS fixed widths (1023px, 640px, …) suggest broken small screens | They are all inside `@media` blocks for *larger* breakpoints; the mobile rules are thorough (which is why the `styles/` tree already passes a responsive review). |
| `service-worker.js` caches aggressively | It refuses to cache HTML under asset URLs, uses `no-store` for the auth bundle, installs atomically, and has an explicit network deadline. Deliberate, documented. |
| `mount-safety.js` wrapping every `__mount*` global | It preserves `aria-busy` ownership and uses a generation counter so a stale async mount cannot overwrite a newer render. Correct. |
| `a11y-*-patch.js` observer files look like duplication | They are the project's established pattern for fixing markup across ~100 independently authored widget files without editing each one. Following it is the lower-risk choice. |
