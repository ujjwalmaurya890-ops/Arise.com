# Arise.com codebase audit — 2026-10-28

## Scope and repository map

Inspected the tracked repository tree (278 files before this audit), package/lockfiles, application entry, all 124 `src/` files, generated assets/chunks, styles, server and Netlify functions, Firestore configuration, service worker, scripts, tests, CI workflow, and project docs. Working tree was clean before the audit. Runtime is Node 22.22.3/npm 10.9.8; `package.json` requires Node `>=22.22.0 <25`.

- **Client:** static HTML entry `index.html`; precompiled React dashboard in `assets/app-bundle.js` (the original React/Vite source project is not present); vanilla JavaScript feature modules in `src/`; 110 listed scripts are assembled into 12 content-hashed chunks by `scripts/tools/build-widget-chunks.cjs`. Most state remains browser-local; reviewed state is account-namespaced and synchronized through the secure API.
- **Build/serve:** `scripts/build.mjs` creates `dist/`, copies the public shell/assets, bundles `src/cloud/auth-entry.js` with esbuild, and checks that privileged server files/secrets are absent. `scripts/serve.mjs` serves `dist/` and same-origin function handlers on port 8123. Netlify publishes `dist/` and has SPA/API redirects and response headers.
- **Identity/cloud:** Google Firebase Auth client bundle; Netlify Functions call shared server code in `server/`; Firebase Admin/Firestore is the only cloud data path. `server/access.cjs` checks verified Google identity and the server-configured five-address allowlist on protected calls; Firestore rules deny direct client access. `/api/sync` is retired with HTTP 410.
- **Persistence/offline:** audited `localStorage` keys are in `src/cloud/storage-schema.js`; attachment bodies live in two IndexedDB databases. `storage-bridge.js` scopes local caches by UID and journals writes; `sync-engine.js` handles cloud restore, retries, conflicts, attachments, backups, and migration. `service-worker.js` caches the app shell/chunks while bypassing protected API calls and fetching security scripts network-first.
- **Integrations:** Netlify Functions provide authenticated AI and cloud routes plus public coding-profile proxies (LeetCode, CodeChef, GFG); other coding-platform requests are made from the browser. External providers were not contacted in this sandbox.
- **Tests/CI:** Node/jsdom regression files are run by `scripts/_run-test.cjs`; cloud/auth/sync tests use Node's test runner; real Chromium checks use Playwright + bundled Chromium; Firestore rules tests require a local emulator. CI also runs build, tests, npm audit, emulator and Chromium jobs. No lint/typecheck script is defined.

### High-risk areas reviewed

1. Auth gating, five-account allowlist, Firebase Admin/Firestore transaction boundaries, API response caching, and the retired shared-code sync endpoint.
2. UID-scoped storage, old local-data migration, offline journal/retry/conflict handling, IndexedDB attachment bytes and backup restore.
3. Service-worker cache upgrades and security-script fetch behavior.
4. Generated chunk/source parity and the 110-script lazy-loading pipeline.
5. Hand-built HTML templates in the independent widgets, user/API data paths, external proxies, and deployment headers.

## Additional security and deployment risks (not confirmed exploitable bugs)

- The configured CSP is only `base-uri 'self'`; it does not establish a `script-src` or `frame-ancestors` policy. Because the page uses inline scripts, a stronger CSP needs a deliberate nonce/hash and third-party-origin plan. No XSS exploit was demonstrated in this audit; this remains defense-in-depth work.
- AI and public coding-profile proxy routes have bounded payloads/timeouts and tests, but no explicit per-account/IP rate limit was found. Authenticated AI use is limited to the five approved identities, while coding-profile endpoints are public and cache for five minutes. Review provider/platform quotas before exposing these routes more broadly.
- Production Google/Firebase sign-in, the real five-email policy, Firestore transaction/rules behavior, Netlify headers/functions and upstream coding APIs could not be verified: no production credentials/config were present, and the rules test was skipped without an emulator. The application correctly fails closed in this state.
- Full WCAG 2.2 AA contrast, screen-reader testing, Safari/Firefox behavior, complete dialog/menu keyboard review, and real-user Core Web Vitals were not established. Existing targeted tests cover portions of these areas; they are not a complete conformance claim.

Before the fix, detailed Chromium traces at 1366–1440×1000 showed the Quick Actions card moving out of the viewport as the two lazy readiness cards mounted; observed CLS was 0.2464–0.2565. Do not treat these small-sample lab values as production Core Web Vitals.

### G. Security, privacy and backend

- No `.env`, Firebase service-account file, private key or production credentials were present; the unconfigured server remained fail-closed. The final scan covered all 15 present changed/new files and found no private-key or high-confidence credential/token patterns.
- `npm audit` found no known dependency vulnerabilities. Storage audit still calls out the two dynamic expressions above.
- Actual local responses now apply `X-Content-Type-Options: nosniff`, `Referrer-Policy`, and `Content-Security-Policy: base-uri 'self'`. The CSP remains intentionally limited; it does **not** yet define `script-src` or `frame-ancestors`. No exploit was demonstrated; this is defense-in-depth work, not a claim of XSS.
- Auth/cloud transaction, UID isolation, backup, retry, and related API behavior are covered by the 51 passing cloud tests and fixture-backed browser flow. Real Google/Firebase sign-in, the configured allowlist, Firestore rules and Netlify production functions were not contacted. Firestore emulator tests skipped for lack of an emulator.
- No explicit rate limit was found for the public coding-profile proxy routes; assess provider quotas before exposing them more broadly.

### H. Accessibility, responsive UX, SEO and compatibility

- Chromium smoke checks found no horizontal document overflow at 390, 768, 1024 or 1440 px; mobile restore passed. Keyboard navigation for the new DSA tabs passed. Theme/image verification covered 41 theme transitions at three viewports.
- Existing targeted compatibility tests pass (11 cross-browser assertions), but real verification was Chromium-only; Safari and Firefox were not run. The full application has not received a complete WCAG 2.2 AA contrast, screen-reader, dialog/menu focus, or reduced-motion audit.
- Static title/metadata, `robots.txt`, redirects and SPA routes were reviewed. No external search crawler/indexability test or production SEO measurement was performed.

### I. Remaining work and readiness decision

**Decision: staging/manual-QA ready; production readiness is not established by this sandbox audit.** No production deployment was made. Before a production decision, configure a non-production Netlify/Firebase environment and approved test identity, run Firestore rules against an emulator, verify real headers/functions and Google sign-in, check provider quotas/rate limits, and collect field Web Vitals. A deliberate nonce/hash and origin plan is needed before tightening CSP. Run full screen-reader/WCAG and Safari/Firefox passes if those are release requirements.

No registered QA-001–QA-005 defect remains open. The unresolved items above are environment-dependent validation and broader security/accessibility follow-up, not silently passed checks.
